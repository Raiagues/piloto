## Palette
Use the reference's deep navy (#04111e), navy canvas (#06182b), panel (#071d32), near-white text (#edf6ff), muted blue-gray (#8fa5bb), blue accent (#62aaff), and green presence (#33d4a0). Borders use rgba(145,190,232,.20); stronger canvas borders use rgba(148,204,255,.44).
Recording uses a navy-blue gradient (#153e60 to #102e49), a blue border (#528dbe), and pale blue text. The active state uses a teal-blue surface (#123c50) and mint microphone/timer accents.

## Layout
Fit the workspace into 100dvh. Keep page scrolling disabled; long transcripts scroll inside their panel.
A collapsible navigation rail separates Live (`#ao-vivo`), Manual (`#manual`) and Automated (`#automatizados`). Follow the Norte reference's outlined icon nodes, navy gradient and slim blue active marker, keeping this project's monospace type. The rail is 72px collapsed and 224px expanded on desktop; on mobile it overlays instead of shrinking content. The expanded mobile rail dims and makes background content inert; Escape or the backdrop closes it. Use accessible labels for collapsed icons. The expanded rail shows the Norte mark and local-model status at its foot.
Live's header contains the editable meeting name, actual start date/time, audio button/timer, local participant and share button. The restart icon begins a new take without deleting history. Center audio controls within the page beside the rail; on narrow screens use a separate centered row. Manual and Automated headers show their page title and provider status.
Live's largest region retains the Canvas/Classifier tabs and drag-to-split behavior. Use the subtle 24px grid in the empty canvas. Manual/Automated show only the Classifier, without the Canvas toolbar. Their left input pane uses State/Questions tabs, defaulting to State; only Live retains the vertical State/Questions splitter. Input/output and workspace/history dividers remain resizable on every page.
Live's lower area is Transcription; Manual's is Tests. Do not add a Transcription/Tests tab strip. Key points remain removed. Drag the separator above the lower area to adjust its height.
Transcription entries use a narrow monospace timestamp column and a text column, with a small microphone-owner label. Separate entries with faint borders. Unconfirmed text is visibly marked, and live text uses a softer blue. The download icon exports source records, temporal windows and real model responses.

## Classifier inspection

Follow the TypeSafe playground structure: input on the left, a flat answer table on the right. Live and Manual default to State above Questions; Automated defaults to tabs. State and Questions share one test identity and form the same request, not independent tests. Drag a title onto the input body to stack, or onto the shared identity/header to merge into tabs; two icon buttons (overlapping tabs / stacked rectangles) offer a keyboard/touch alternative. Entering stacked mode resets the test editors to 50/50; subsequent divider drags remain adjustable. Stacked mode shows actual pane headings, not an extra tab strip. Tabs support arrow keys and an unapplied-edit marker. Persist layout independently in each test-page draft. Keep thin dividers, compact headers, line numbers for Questions and real keyboard/pointer resize handles. Minimum sizes keep Run visible. Narrow classifier panes stack input/output; scrolling stays inside panes.

State shows the exact model input as JSON, updating during speech. When a window cuts an unfinished recognition sentence, restore its bounded prefix from the same source result. The timing tooltip and downloaded session JSON identify that overlap. Questions is the editable question map without a redundant model wrapper. Apply or Ctrl/Cmd+Enter validates the draft; invalid JSON never replaces the active contract. Default instructions are English with Portuguese class keys; preserve user-edited questions across UI upgrades.

Use one expandable row per question: key and exact instruction, result, primitive type. Only show answers matching the displayed State, confirmation status and applied questions. Older results stay in the export rather than a card feed. Keep the result area visual-only: labels, colored markers, scores and percentages. Do not render per-answer JSON or a request/response disclosure. Raw data remains in the session export; State and Questions retain their JSON editors.

Score shows its weighted mean/maximum, one dot per criterion, and the most probable level with its probability. The mean is not the winning level or confidence. Highlight the most probable level, not a rounded expected score; label ties explicitly. Choice uses categorical colors plus a probability-colored percentage. Noul is explicitly labeled P(true), with a colored marker and meter. Low/mid/high probability accents are coral/amber/mint; never label them accuracy. Color is redundant with numeric values, labels and hover descriptions. Expand rows for alternatives and percentages without code blocks. Keep concise loading/error states and never fabricate missing responses. A small 'Incerto' label marks diffuse distributions; its tooltip explains the uncalibrated UI thresholds. This label does not modify model outputs.

Live/Manual are sidebar destinations, not controls inside State. Automated is a third sidebar destination, not a mode inside Manual. Live retains the read-only JSON view. Manual is a plain text editor with a test name, PT/EN/FR/ES tag, repetition selector (1/4/10), Run and Use example; New belongs in the table header. Do not offer Save case. Manual edits never change recorded speech; Live restores the meeting's question contract. Entering Manual pauses audio while retaining late final results; returning never starts the microphone automatically.

Manual State is directly editable without a Text/JSON selector. JSON-looking input is parsed and validated; ordinary text stays literal. Place Run/repetitions and Use example next to the compact name in the shared top bar; Stop appears while running. The pencil precedes the name. Wrap the toolbar on narrow screens. New test belongs in the Tests table heading. A fresh Manual or Automated draft, and New test, start with one empty State, empty Questions, no expected answers and one repetition. Do not seed meeting speech or the example implicitly. Existing drafts and archives survive navigation/reload/upgrades; New clears only the current page's draft. Use example alone restores workbook-v2 Questions, context and expected labels, without calls or history deletion. Empty Questions are valid only in local drafts: strict request/archive validation still requires at least one question, and Run stays disabled until State and applied Questions are valid. CSV remains a real compact outlined button; do not restore Load/Download JSON, Backup or Import controls.

Manual/Automated rows show key/instruction on the left and explicit **Esperado / Obtido** columns together on the right. Use readable 13–15px values, neutral pale-blue text, native navy selectors, and visible keyboard focus. Never color true/false or probability values red/green: reserve these colors for pass/fail badges. Move the primitive type and full distribution to expanded details. On narrow output panels move the pair below the question, keeping Expected and Obtained adjacent. A Testes heading precedes Summary / Execução 1 / Execução 2 selectors, which wrap instead of requiring horizontal scrolling. Before running, render the selected number of neutral, disabled pending executions. Actual runs have green checkmarks for passing and red crosses for failing; API errors use a red exclamation mark. Tooltips distinguish wrong answers and insufficient confidence, and missing expectations stay neutral. Summary shows the most frequent answer, its mean probability, and how many executions passed; indicate ties and varied answers. Do not render an Estatísticas disclosure. Keep only approval counts and average/individual duration in seconds beside the selectors. No per-row metric paragraphs or raw JSON. Expected answers are never sent to the model.

Place `Conf. mín. ≥ [85] %` directly below Expected and the obtained answer's probability directly below Obtained. Load `minProbability` automatically (0–1 in data, 0–100 in UI); an empty field means no threshold and zero is real. Tooltips distinguish probability from the API's `confidence`. False uses 1−P(true). A correct answer below the gate says “Falhou · resposta correta, confiança insuficiente”; a wrong answer says “Falhou · resposta diferente”; both conditions passing says “Passou”. Summary verdicts evaluate individual runs, never approve by mean alone, and identify mixed failure causes. Remove duplicate P(expected)/minimum sentences. Keep missing expectations/API errors distinct from passing results. Expectations remain editable after execution; corrections update separate metadata without changing model responses.

Tests uses one flat execution table with a single heading/action row, without a Saved cases filter, internal tabs or second toolbar. View restores an executed test's exact input and results, which can be edited and rerun. State, prompts, original expectations and responses remain frozen per batch; corrected expectations are separate metadata. Consistency is not accuracy. Successful saves and deletions are silent; failures stay visible. Keep confirmation before deletion. Legacy case records remain in storage, but have no controls in the UI. New test and Download CSV are real compact outlined buttons in both Manual and Automated. Do not show Backup or Import controls. CSV uses seconds and the latest corrected expectations.

Each test row has a navy outlined checkbox, with a pale-blue check/mixed marker and keyboard focus; the table header selects/deselects all and shows the mixed state for partial selection. Test titles have a small pencil and can be renamed inline; Enter/check saves, Escape/cross cancels. Rename updates only persisted display metadata, never frozen inputs, expected labels or model outputs; use the display name in comparison, exports and deletion confirmations. Failed writes leave the old name intact. Only when selection is nonempty, show its count and Compare/Delete/Clear in the existing heading row. Comparison temporarily fills the classifier workspace with flat, divided columns, one per selected batch, using the existing visual answer rows and colors. Keep State expandable, exact question instructions, saved expected values and per-batch means/timing visible; never pool different tests. No raw JSON or new inference calls. Back restores the untouched editor; View opens an individual batch. Overflow remains within the output panel. Bulk deletion confirms the selected count/names and removes only those batches; successful deletion stays silent.

Do not show a green connection dot at the bottom of the sidebar. The collapsed rail has no footer; expanded navigation can show provider status as plain text. The manual title has a compact plain-text provider label, without reinstating the removed output bar. Distinguish a configured official key from a connection verified by a successful call; display missing-key instructions without exposing its value. The JSON import note is provider-specific: official Jev receives the original JSON unchanged, local jevos uses the documented Noul adapter. The Run tooltip discloses remote API usage. Label historical results by their original provider in summary, comparison and the existing date metadata line; never imply old local results came from official Jev. Keep secrets exclusively in the server's ignored `.env`.

Remove the redundant Key & instructions / model / Primitive type output header. Keep types in live/comparison answer rows and inside expanded manual rows, model status in the sidebar, and live latency unobtrusively below the answers. All visible inference durations use seconds with three decimals, including summary and individual views. Raw JSON retains its explicitly named `latencyMs` field for archive compatibility.

Raise minimum State/input pane sizes while Manual is active so the editor and Run control remain reachable on small screens. Restore saved splitter preferences when leaving it.

## Memory flow experiment

Current phase (UI revision `20261005-30`): new executions use the **Thread worker** contract below. The older relation-worker descriptions in this document are historical compatibility contracts, not instructions to call `has_relation` in new runs. Saved relation tests remain inspectable without replaying or migrating their outputs.

The independent `#memoria` page starts empty when there is no recoverable execution, with an Input JSON editor and no example button. Keep its storage separate from the existing test archive and audio ledger: `norte.memory-flow.v1` stores the session draft, `norte.memory-library.v1` holds explicitly saved test snapshots and question versions, and `norte.meeting-memory.v1` automatically checkpoints the active execution's memory in this browser. The JSON batch contains ordered cases with id, current_utterance, expected_store_memory and expected_event_type (null for rejected expectations). Each chunk makes a gate call, then a type call only when the actual gate accepts it. Neither expected labels nor prior chunks are sent to the model.

Questões opens a large, resizable, soft-wrapped, syntax-colored native JSON editor. Its dimensions persist in `norte.memory-ui.v1`, independently of test data, and remain bounded by the current viewport. Questions are directly editable even when inspecting an archived test: only an explicit Salvar versão creates Q001, Q002, etc.; equivalent content reuses its version, ignoring formatting/key order. A successful write shows a green “✓ Versão Q… salva” status and a disabled “Salvo” button until the next edit; errors never show a success confirmation. There is no compare control, edit-copy gate or autosave timer. Invalid/incomplete JSON stays in the draft, creates no version and blocks execution. The two routing question IDs/types remain required, but destinations come from the editable `event_type.criteria` keys (the existing Choice validation accepts 2–12 options). Add, rename or remove a criterion to change the map after explicit save. Removed expected labels are preserved in the input draft and flagged for correction before execution; never silently rewrite a gabarito. Each run retains its exact question snapshot. Saving changed questions or applying input changes detaches a draft without rewriting an archived request or result. Backdrop clicks, Escape and close buttons offer Save, Discard and Continue editing when dirty; invalid JSON cannot close through Save.

All shared JSON editors use Tab to insert two spaces or indent selected lines and Shift+Tab to unindent. Preserve focus, selection, scroll position, syntax highlighting and native undo; read-only editors must not be modified.

Executing, typing, applying input, reloading and clearing never automatically archive a test or create a question version. Salvar explicitly retains the current configuration/result, memories and question snapshot; Salvo indicates it is archived. Unsaved working state can recover within the same tab's session, but is not a history entry. When the session draft is absent, recover the active execution from its local memory checkpoint; interrupted calls are never retried automatically. Before replacing unsaved work, offer Save, Discard and Continue editing. Existing saved tests remain immutable. Testes toggles a resizable table whose whole rows open their batch, questions and original outputs with mouse or Enter/Space. Display IDs such as T001_B001, a separate Q001 column and colored correct/divergent/error counts; omit the redundant completed label and per-row question button. Limpar clears the active memory checkpoint while preserving the saved library. Storage errors remain visible, and a checkpoint changed by another tab must not be silently overwritten.

Each execution owns two explicit structures. `meeting_events` is append-only during the run: after a successful true gate and valid type response, store `{event_id, chunk_id, timestamp, type, text, status, store_confidence, type_confidence}`. IDs E001, E002… count accepted events, including accepted-but-incorrect predictions; no Ignore, API-error or half-classified entry becomes an event. Confidence values are P(true) and P(actual type), not API confidence/concentration. Timestamp is the chunk's arrival time relative to execution start, formatted HH:MM:SS, not response completion time. The category queues are grouped views of this same memory. `raw_window` is the last four received chunks in arrival order, including pending, ignored and failed chunks; receive before classification and evict oldest on the fifth arrival. It contains `{chunk_id, timestamp, text}` and never uses expected labels as a filter. Its eviction does not remove diagnostic records needed to inspect old paths. Both structures are materialized in run snapshots and reconstructed from verified records for legacy restoration. Starting a new execution resets its memory and clock; saved runs remain separate.

Event `status` is a system-owned creation default: actual types `hypothesis` and `test_proposal` start `open`; observation, test_result, requirement, decision and all other/custom types start `active`. Never infer lifecycle state from wording, expected labels, confidence or verdicts, and never ask the model for status. No later-chunk lifecycle transitions exist yet. Restoration supplies the same defaults to legacy events without repeating inference or changing the source archive. Expose status in expanded event metadata without changing the compact row or diagram. This is separate from the execution status of a run/record and absent from raw_window.

Keep the existing flow nodes, connections, zoom and pan. Separate `meeting_events` and `raw_window` blocks sit beside the map (below it on narrow screens), with counts, independently scrolling/collapsible lists and desktop width/height dividers. Use compact rows, not expanded cards: IDs, event type, a verdict symbol and a one-line Input preview. Clicking a row selects its path and toggles inline details with the complete current_utterance, IDs, relative timestamp, type and both probabilities. Selecting elsewhere highlights the row without expanding it. Preserve disclosure and FIFO scroll during updates; inspecting an older chunk never rewinds or mutates raw_window. Persistent here means local browser recovery, not a server/database or an automatic entry in the saved-tests table. The memories never enter the chunk classifier's State and are not connected to live-audio transcription. The separate relation worker uses eligible meeting_events as described below.

Panel-shaped SVG icon buttons hide chunks, test details or both memory lists, returning their space to the map. Matching buttons in the canvas toolbar always remain available to reopen each panel; labels/tooltips identify the panel and action, and aria-expanded tracks visibility. Persist visibility independently in `norte.memory-ui.v1`, preserving prior divider sizes and keeping selection/results unchanged. This works with side-by-side desktop, lower memory panels on tablets and the mobile chunk rail.

Collapsed question summaries use two compact lines: question ID plus response verdict (not Noul/Choice); Esperado with its value and minimum required confidence; Obtido with its value and actual probability. The expected confidence is a threshold (≥), never an invented expected-class score. Color answer agreement green/red independently from probability green/amber; a wrong high-confidence answer remains red with a green probability, and a correct low-confidence answer remains green with an amber probability. Missing/unvalidated comparisons stay neutral. Hover explanations distinguish a probability meeting its threshold from a correct answer.

Use the dark grid canvas with `raw_window → should_store_memory → event_type → category → meeting_events`, plus the false branch to Ignore. The input block is the actual four-chunk raw FIFO, not a copy of whichever historical input is selected. Each configured category has its own outgoing arrow into the shared meeting_events node; that list appends accepted events in arrival order as each classification completes. Both map lists project the existing structures, not separate stores. They are visible by default, independently collapsible/resizable (320px natural default), with inline arrival animation and a packet along the final storage connection; respect reduced motion. Selecting a stored event reveals it within that map list without moving the camera. An evicted selected chunk gets an explicit “fora da janela atual” cue, never a rewind of raw_window. The sidebar memory inspectors remain available for complete metadata.

The default questions supply eight categories, including requirement; node rows, both sets of category edges, queues, collapse controls and probability details follow the active question snapshot, including when reopening an older test. Keep custom questions unchanged and restore archives without question snapshots against the original seven-category contract. Category labels are data, not HTML/CSS selectors or gate identifiers. Category and Ignore lists default collapsed unless an explicit persisted preference says otherwise; their bulk toggle does not collapse the two independent stream nodes. Highlight only the selected chunk's actual route, including its category-to-memory edge when stored. Blue means in progress; green means correct; red means a store/type mismatch; amber means a correct response below the fixed 80% probability warning threshold. API errors must be labeled as execution errors, never classified as Ignore or silently retried. Ignore is an inspection log, not memory. Queues route by actual outputs even when their expected verdict fails. Selected queued chunks have no inferred path. This map change does not send raw_window or meeting_events to the model.

The ordered chunk rail keeps current versus selected status distinct. Clicking a previous chunk pauses following, not execution; selecting the currently running chunk resumes following, with no separate follow button. Completed chunks are slightly muted but readable and interactive. Label source text Input · current_utterance, not as a model explanation. Keep expected/obtained/confidence rows compact; put id/type/timestamp in the chunk title tooltip. Hovering/focusing a verdict shows a tooltip with one colored dot and explanation per line; do not show permanent legend dots. Do not show the old FIFO/Ignore footer or confidence footnote. Each question expands inline in the response panel, never in a results popup. Keep expected and obtained answers side by side, with classification correctness separate from a low-probability warning. Sidebar width and history/response heights use draggable, keyboard-accessible dividers with persisted preferences; double-click resets a divider. Expansion reserves more room only when the user has not chosen a response-panel height. Boolean criteria use blue for false and lavender for true, not verdict red/green. Show class probabilities highest first, with a numeric percentage and a small lavender progress ring; individual class descriptions and the original colored request/response JSON are expandable. Keep the API confidence statistic separately labeled. Preserve disclosures while selecting chunks or receiving outputs. Missing type calls remain explicitly not consulted, with no invented zero probabilities.

On the map, raw_window and meeting_events are shared containers and keep neutral backgrounds. The raw_window border follows the selected route; meeting_events keeps a neutral border. Apply verdict color only to the selected chunk's entries, its routing nodes and edges, not to every event in a queue. Unselected queue entries use opaque neutral backgrounds so a routing node's tone cannot tint them. Highlight the matching raw entry in both the map and side inspector, if it is still among the last four arrivals. An evicted selection may highlight the raw node's route border, but never any unrelated current FIFO entry. The side inspectors retain per-item result symbols independently of selection.

The Chunks header has a persisted execution-mode switch. Off is **Passo a passo**: receive and process one chunk at a time, retaining the existing visual pacing. On is **Rajada**: simulate up to four arrivals every 120ms independently of inference, with no artificial per-response or between-chunk visual waits. This simulates a busy incoming stream; it is not live audio or a claim of faster model latency. Keep a serial FIFO inference worker and the same conditional gate/type requests. A raw_window eviction never removes pending work. Received but unprocessed chunks show “Na fila”, contribute to a pending count, and have no inferred route; automatic following tracks the processing chunk, not the latest arrival. Manual inspection remains selected as arrivals continue. Choose the mode before executing; freeze it in the run snapshot and disable the switch while busy. Record receipt time separately from processing start, so meeting timestamps remain arrival-based under backlog. Stop/fatal errors halt both receipt and processing, interrupt queued entries and never retry or auto-resume on reload. Executing still does not automatically save tests or question versions.

### Relation worker — first stage

The memory toolbar's **Exportar** control offers JSON and CSV downloads for the entire currently open test, including an unsaved result or a restored saved test. Do not limit the download to the selected chunk. Export is local/read-only: no inference, automatic test/version save, local-storage changes or network uploads. Disable it with no input or while either worker is running; stopped/error/interrupted tests and input-only drafts remain exportable, with missing answers explicit. The execution's frozen Q/RQ configuration takes precedence over any edited draft. Close the format picker on outside click, focus leaving or Escape; retain normal keyboard navigation.

JSON uses `format: "norte.memory-results"`, schema_version 1, IDs/versions/export time, original batch including gabaritos, configuration, summary, complete execution snapshot, normalized question_results and deterministic filter_results. Preserve original request/response objects and metadata, full instructions/criteria, all probabilities, model confidence separately from P(answer), timestamps/errors, both worker jobs, meeting_events/raw_window/relations and skipped questions. CSV carries common test/version IDs and a record_type discriminator: test, chunk, question, filter, meeting_event, raw_window, relation, relation_job and relation_call. Each question has expected/actual/threshold/match/confidence columns plus full JSON details; JSON detail cells preserve structures not naturally tabular. Probabilities use the unrounded 0–1 scale. New v3 relation runs export a complete boolean expected value for every actual prior pair; configuration.relation_expectation_policy is positives_only. Historical v1/v2 runs retain explicit_pairs and their original unknown expectations. Not-consulted, pending and failed questions have no invented answers or scores. Quote all CSV cells, use UTF-8 BOM/CRLF, neutralize spreadsheet formulas in user-authored text, and keep originals intact in JSON. Sanitize download filenames; downloading does not imply that the export envelope is accepted by the batch input importer.

Each saved-test row offers Excluir independently of row navigation. Confirm the exact ID before removing it; cancel, Escape and outside click do nothing. Deletion is disabled during execution and writes only the latest library transaction, preserving other tests and all Q/RQ versions. A failed storage write leaves the library unchanged. If deleting the open test, retain its result as an unsaved draft, without autosaving it back into history. Keep a persistent nextTestNumber high-water mark so deleted IDs are never reused. Deleting another row must not open that test or discard the active draft.

Draw the relation worker as a separate environment below the chunk flow, with **no edge between workers**. Its input is another live view of the same `meeting_events`, not a separate store or a visible work-FIFO node. For all new executions, this input points directly to Jev has_relation, then branches into **Tem relação · true** and **Não tem relação · false**. Hide the old filter/approved/rejected nodes and edges. Compare every new event with every previously stored event regardless of type/status, including closed decisions and custom types; exclude itself and future events. Freeze that complete prefix at enqueue. Work still uses an independent internal FIFO, so chunk ingestion never awaits relations. Both meeting_events views append together while relation calls are pending. The input mirror starts expanded; both grouped output lists start collapsed unless saved preferences say otherwise. Preserve resizing, collapse choices, selection and replay.

Each output list contains expandable source-event groups (for example E031), each containing its corresponding target events and response probabilities. Keep groups for all processed sources instead of replacing them with the latest source. Cache audit projections and create child rows only for opened groups. Counts refer to pairs, with source-group counts in hover text. Clicking a group shows its complete expected/obtained rows in the lower inspector; clicking a child reveals that row. Label input text current_utterance. New-run stage tabs are Event, true and false; Event includes pending/error pairs, never treating them as false. Ver chunk restores the original chunk questions. Manual selection and selected stage survive updates/reload without moving the processing queue.

Accept direct root-level `expected_relations: {C03: {}, C08: {C04: {has_relation: true}, C06: {has_relation: true}}}`. ## Thread assignment — current memory pipeline

New runs carry `memorySchemaVersion: 2` and `thread_worker.schemaVersion: 2`. They have four collections: `raw_window` (last **15** received chunks, including ignored/error/pending chunks), `meeting_events`, `meeting_threads`, and `meeting_relations` (empty in this phase). New threaded events contain `{event_id, chunk_id, timestamp, type, text, status, thread_id, thread_assignment_state}`. The assignment state is `pending` until assigned, then `assigned`; a null thread ID stays pending, including uncertain/error/interrupted jobs. Omit store/type confidence fields from the memory and all hydrated thread inputs. Do not send assignment metadata as linguistic evidence. Original question outputs still retain their complete probabilities for inspection and export. Historical snapshots retain their original worker policy and event schema.

The primary gate/type worker creates events immediately. A separate FIFO assigns threads, using the existing independent secondary HTTP lane; never await it inside primary processing. The FIFO freezes the five preceding received chunks at each event's arrival, including ignored utterances but excluding the current event (already in `current_event`) and all future arrivals. Reconstruct this prefix from the receipt records, not the potentially newer raw-window view.

The first stored event creates T001 without inference. Subsequently send the current event, frozen recent_context and active thread with fully hydrated anchors to `belongs_to_active_thread`. `belongs` with P(chosen answer) >= 0.80 assigns the active thread; `does_not_belong` with P(chosen answer) >= 0.80 queries archived threads. Any answer below 0.80 leaves `thread_id: null` and `thread_assignment_state: pending`, without querying archives, creating a thread or changing any existing thread/anchor. `uncertain` remains pending at any probability. The 80% boundary is inclusive and uses the answer distribution, not the API's separate confidence value. Archived queries use dynamic `belongs_to_archive_thread__T…` IDs in the same request, each scoped to its corresponding entry in `state.candidate_threads`. Hydrate every anchor with its actual event text/type/status, not only IDs. Batch only when required by actual request/question/State limits; never discard anchors. A thread that cannot fit is a visible execution error, not a negative match.

Exactly one archived `belongs`, with all others `does_not_belong` and EVERY consulted answer >= 80%, reactivates that thread and archives the previous active thread. All confident negatives (including an empty archive after a confident active rejection) create the next sequential thread. Any low-confidence archive answer, uncertain archive or conflicting positive matches leaves assignment pending and preserves the current active thread. Errors/interruption never fabricate a thread. Every assigned event is appended to its thread's `anchor_event_ids`; pending events never become anchors and are not automatically retried. Thread objects retain `{thread_id,status,title,created_by_event_id,anchor_event_ids}`, with title taken from their first anchor text.

Recovery of v2 validates both planned calls and decisions against the gates; derived event assignment states are reconstructed, not trusted from saved memory projections.
